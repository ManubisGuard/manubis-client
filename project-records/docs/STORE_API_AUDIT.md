Date: 2026-10-15

## Executive summary

The checked-out Amnezia client already includes an **Amnezia Gateway** integration for service discovery, VPN config import, account information, and App Store / Google Play in-app purchases. This is not the same thing as a complete ManubisGuard web shop. Existing purchase flow validates platform-store transactions through the configured Gateway and imports a VPN config returned by that Gateway. No evidence has yet been found in this client code for a direct wallet, arbitrary payment provider, coupon engine, or order-management API.

The user says the API key was generated by the ManubisGuard/PasarGuard panel. The panel's dashboard URL and key are not necessarily enough to use the Gateway endpoints: the client currently speaks a separate Gateway API contract. We must inspect the panel API and its authentication/schema independently before designing the adapter. Do not send the supplied key to unverified endpoints.

## Existing client integration found

### Gateway endpoint

- `client/core/repositories/secureAppSettingsRepository.cpp`
  - Default Gateway endpoint is `http://gw.amnezia.org:80/`.
  - Endpoint is stored as `Conf/gatewayEndpoint` and can be changed/reset via settings.
- `client/core/controllers/gatewayController.*` handles HTTP requests.
- `client/core/utils/api/gatewayPayloadBuilder.*` builds request JSON containing app/platform metadata, app version/name, distribution channel (when available), language and installation UUID.
- `client/core/utils/constants/apiKeys.h` defines the Gateway request/response fields.

### Existing Gateway endpoints referenced in client source

- `POST v1/services`: service catalogue and plan metadata (`ServicesCatalogController`).
- `POST v1/config`: imports a VPN configuration (`SubscriptionController`).
- `POST v1/trial`: requests trial config.
- `POST v1/revoke_config`: revokes imported config.
- `POST v1/account_info`: account/subscription status for an imported service.
- `POST v1/renewal_link`: requests a renewal URL.
- `POST v1/native_config` and `POST v1/revoke_native_config`: native config lifecycle.
- `POST v1/get_subscription_info`, `v1/subscriptions`, and `v1/restore_subscription`: platform-store purchase/restore flows (`StorePurchaseController`).
- `POST v1/news`: Gateway news feed.

These are paths found in the client source, not confirmed endpoints on the user's panel.

### Existing UI

- `client/ui/qml/Pages2/PageSetupWizardApiServicesList.qml`: lists services from `ApiServicesModel`.
- `client/ui/qml/Pages2/PageSetupWizardApiPremiumInfo.qml`: displays plan choices. It uses Google Play/App Store billing on supported store builds; otherwise it opens a `checkoutUrl` if one is supplied by the Gateway catalogue.
- `client/ui/controllers/api/subscriptionUiController.cpp`: handles service selection, account info and store purchase orchestration.

### Important implication

The existing UI is a useful starting point for service/plan selection, but it is Amnezia-branded and built around Gateway-specific payloads. It should not be pointed directly at the PasarGuard panel just by changing a URL. The ManubisGuard store should use a stable Store Backend API and a server-side panel adapter unless panel source inspection proves that a safe, complete existing contract already fits.

## Security constraints

- Never store the user's API key in this document, Git, Android resources, logs, or APK.
- The key was posted in chat; recommend revoking it and creating a least-privilege replacement.
- Do not use panel admin credentials from the Android app. Keep panel communication server-side.
- Verify payments server-side before activating/renewing subscriptions.
- Do not treat a client-supplied order/payment state as proof of payment.
